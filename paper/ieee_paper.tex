\begin{abstract}
This paper presents an end-to-end methodology for malware classification using graph neural networks (GNNs) constructed from network flow records. We introduce a principled pipeline that converts raw network flow logs into compact flow-graphs where nodes represent network endpoints or service ports and edges encode directional flow features and temporal summaries. The proposed approach leverages modern GNN layers to capture relational structure in flow graphs and to distinguish malicious multi-step command-and-control or data-exfiltration behaviors from benign traffic. We evaluate the approach on a diverse synthetic dataset that mirrors realistic flow-level patterns and show that the GNN-based classifier outperforms conventional flat feature models on several metrics, including accuracy and area under the ROC curve. The system emphasizes reproducibility and deployment readiness: training and evaluation scripts, model export to ONNX, and a minimal FastAPI serving layer are included. We discuss implementation considerations such as batching variable-sized graphs, normalization of continuous flow features, and secure model serving with JWT-based authentication. The paper also analyzes failure modes, security considerations for model poisoning and evasion, and practical limitations in environments where flow sampling or incomplete records reduce graph fidelity. Finally, we outline directions for future work including semi-supervised pretraining on large unlabeled flow corpora, integration with host telemetry, and explainability techniques to assist incident responders.
\end{abstract}

\section{Introduction}

Network-based detection of malicious activity remains a critical component of modern cyber defense. Network flow records, which summarize communication between endpoints, are widely available in enterprise and cloud environments and provide a scalable signal for detecting command-and-control, scanning, and data-exfiltration behaviors. However, traditional flow classification approaches treat flows as independent records and derive flat feature vectors per flow. Such approaches often fail to capture multi-flow structure, temporal correlation, and the relational patterns that indicate coordinated malicious campaigns.

Graph neural networks (GNNs) offer a principled approach to modeling relational data. By representing flow interactions as graphs and learning message-passing operations over nodes and edges, GNNs can aggregate local and higher-order structural context to improve classification. This paper proposes a complete pipeline that constructs network flow graphs from raw flow logs, trains GNN models to classify flows or sessions as malicious or benign, and provides a deployment-ready exporting and serving mechanism.

In this work, we address the following practical challenges: how to convert variable-length flow sequences into compact graphs suitable for GNN training; how to design node and edge features that capture both instantaneous flow attributes and short-term temporal context; how to train GNN models given class imbalance and limited labeled malware samples; and how to serve trained models efficiently in production environments.

The main technical contributions of this paper are:

\begin{itemize}
	\item A flow-to-graph construction procedure that converts raw NetFlow/IPFIX-style records into directed graphs where nodes represent endpoints or tuple-aggregates and edges represent observed flows enriched with statistical summaries.
	\item A GNN architecture based on GraphSAGE and Graph Convolutional Network (GCN) building blocks, adapted for flow graphs with heterogeneous node attributes and temporal aggregation.
	\item Practical training recipes for handling variable graph sizes, class imbalance, and reproducible evaluation including ONNX export for inference and a FastAPI-based serving component for real-time analysis.
	\item An empirical evaluation on a synthetic but realistic dataset showing improved detection performance compared to flat-feature baselines and analysis of failure modes relevant to operational deployments.
\end{itemize}

The remainder of the paper is organized as follows. Section II motivates the problem and reviews prior work on flow classification and graph-based learning. Section III formalizes the problem and presents the flow graph construction details. Section IV describes the proposed GNN architectures and training procedures. Section V details the implementation and deployment pipeline. Section VI reports experimental results and ablation studies. Sections VII and VIII discuss security considerations and limitations, and Section IX concludes with directions for future work.

\subsection{Background and Challenges}

Network flow records typically capture the following per-flow attributes: source IP, destination IP, source port, destination port, protocol, byte and packet counts, start time, end time, and flags. Let each raw flow record be denoted as a tuple f = (s, d, sp, dp, proto, bytes, pkts, t_start, t_end, flags). A naive approach maps f to a feature vector x_f and trains a standard classifier. While this can be effective for simple single-flow anomalies, many malware behaviors are characterized by patterns across multiple flows: repeated beaconing to a set of command-and-control endpoints, staged downloads across several hosts, or lateral movement inside a network.

Graph construction addresses this by creating a graph G = (V, E) where V is a set of nodes and E is a set of directed edges. We consider two common design choices for nodes: endpoint-level nodes (representing IP addresses or anonymized host identifiers), and aggregate nodes (representing endpoint:port tuples or flow clusters). Edges are created for observed flows: an observed flow from node u to node v corresponds to a directed edge e_{u->v} with an associated feature vector x_e that summarizes the flow attributes and short-term statistics.

Two key challenges arise when using flow graphs in practice: first, graphs are variable in size and degree, requiring batching strategies that preserve structural information; second, the telemetry may be incomplete due to sampling, NAT, or encryption, which can obscure malicious signals. We adopt standard normalization and padding techniques to create fixed-size batches by sampling or truncation and use attention-based aggregation to emphasize salient neighbors.

\subsection{Notation}

We denote a graph by $G = (V, E)$ with $N = |V|$ nodes. The node feature matrix is $X \in \mathbb{R}^{N \times F}$ and the adjacency matrix is $A \in \{0,1\}^{N \times N}$ for unweighted edges, or $A \in \mathbb{R}^{N \times N}$ when edge weights are present. A common preprocessing step constructs the symmetric normalized adjacency.

\begin{equation}
\hat{A} = A + I, \quad \hat{D}_{ii} = \sum_j \hat{A}_{ij},
\end{equation}

and the normalized form used in GCN layers is

\begin{equation}
	ilde{A} = \hat{D}^{-1/2} \hat{A} \hat{D}^{-1/2}.
\end{equation}

For node embeddings $H^{(l)} \in \mathbb{R}^{N \times D_l}$ at layer $l$, the standard GCN propagation rule is written as

\begin{equation}
H^{(l+1)} = \sigma\left( \tilde{A} H^{(l)} W^{(l)} \right),
\end{equation}

where $W^{(l)}$ is a learnable weight matrix and $\sigma$ is a non-linear activation such as ReLU.

GraphSAGE uses neighborhood aggregation functions \text{AGGREGATE} to compute node updates. A commonly used variant concatenates a node's current representation with an aggregation of its neighbors:

\begin{equation}
h_v^{(k)} = \text{ReLU}\left( W^{(k)} \cdot \text{CONCAT}\left(h_v^{(k-1)}, \text{AGGREGATE}\left( \{ h_u^{(k-1)} : u \in N(v) \} \right)\right) \right).
\end{equation}

The principal contributions of this paper are the combined data modeling, architectural choices, and practical deployment pipeline that together enable robust malware classification from flow graphs. The detailed contributions are:

\begin{itemize}
	\item A reproducible pipeline to convert NetFlow-like records into compact graphs with node and edge features suitable for GNN consumption.
	\item An architecture that combines GraphSAGE-style aggregation with GCN layers and edge encodings to balance expressiveness and training stability.
	\item Engineering practices for batching variable-size graphs, exporting trained models to ONNX for inference, and serving via a lightweight FastAPI server with JWT-based access control.
	\item An empirical evaluation demonstrating performance gains over classical baselines and an analysis of operational constraints.
\end{itemize}

\section{Implementation Details}

This section describes concrete implementation choices, software libraries, deployment artifacts, and engineering notes needed to reproduce the pipeline.

\subsection{Flow-to-Graph Construction (Expanded)}

We preprocess raw NetFlow/IPFIX-style records into compact directed graphs using a configurable aggregation window $T$ (seconds). The construction pipeline performs the following steps:

\begin{enumerate}
	\item Filter flows by time window and optional IP prefix allow/deny lists.
	\item Aggregate flows by endpoint or endpoint:port tuples depending on the chosen node granularity.
	\item Create directed edges for observed flows. For multiple observed flows between the same node pair inside the window, collapse into a single edge with aggregated statistics (sum, mean, count, min, max, inter-arrival times).
	\item Compute node features by aggregating per-node statistics (degree, total bytes, unique peers, role score) and embedding categorical attributes (protocol, service) via one-hot or learned embeddings.
	\item Normalize continuous features per-dataset using running statistics saved with the experiment configuration.
\end{enumerate}

Algorithmically, the graph construction function $C(F;\theta_C)$ can be implemented as shown in pseudocode:

\begin{verbatim}
function build_flow_graph(F, window_T, node_type="endpoint"):
	keep = filter_by_time(F, window_T)
	nodes = {}
	edges = {}
	for f in keep:
		u = node_id(f.src, node_type)
		v = node_id(f.dst, node_type)
		nodes.add(u); nodes.add(v)
		if (u,v) not in edges: edges[(u,v)] = init_edge_stats()
		edges[(u,v)].update_with_flow(f)
		nodes[u].update_with_flow_out(f)
		nodes[v].update_with_flow_in(f)
	return Graph(nodes, edges)
\end{verbatim}

The resulting graph is then converted to tensors compatible with the chosen graph library (PyG or DGL), including an edge index array, node feature matrix $X$, and an edge feature tensor $E_f$.

\subsection{Feature Engineering}

Key node features used in experiments:
\begin{itemize}
	\item Degree (in/out), total bytes sent/received, packet counts.
	\item Unique peers count and entropy of peer distribution.
	\item Role indicators (server-like: high in-degree on server ports, client-like: many outgoing connections).
	\item Temporal statistics: mean inter-arrival time, burstiness score.
\end{itemize}

Edge features include:
\begin{itemize}
	\item Aggregated byte/packet statistics (sum, mean, max) within the window.
	\item Flow duration statistics and time-of-day encoding.
	\item Flags summary (binary vector) and protocol embedding.
\end{itemize}

All features are standardized (z-score) using statistics computed on the training set. Categorical features are encoded with small learned embeddings.

\subsection{Model Architecture (Expanded)}

The proposed model uses a hybrid GraphSAGE + GCN backbone with edge-conditioned message passing. Concretely:

\begin{itemize}
	\item Input: node features $X$ and edge features $E_f$.
	\item Edge MLP: small MLP that maps $E_f$ to edge weights or modulation vectors used to condition message aggregation.
	\item Message passing: three layers where each layer performs neighbor aggregation (mean) followed by a node MLP; skip connections and layer normalization are applied between layers.
	\item Readout: global mean pooling followed by an MLP classifier with dropout and a sigmoid output for binary classification.
\end{itemize}

We experimented with attention-based aggregation (GAT-style) in an ablation but found mean-aggregation with edge-conditioning offered a favorable accuracy/latency tradeoff.

\subsection{Training Details (Expanded)}

We use the following practical engineering recipes to improve robustness and reproducibility:
\begin{itemize}
	\item Class balancing: weighted binary cross-entropy with positive class weight inversely proportional to its frequency.
	\item Data augmentation: random node/edge dropout and temporal jitter within the window to simulate sampling.
	\item Checkpointing: best model by validation AUC saved and exported to ONNX for inference tests.
	\item Deterministic runs: set global seeds and use deterministic cuDNN flags when applicable; save config and RNG state with each experiment.
\end{itemize}

\subsection{Deployment and Serving}

Trained models are exported to ONNX using PyTorch's \texttt{torch.onnx.trace} or \texttt{torch.onnx.export} utilities with example inputs representative of batched graphs. The FastAPI server loads the ONNX model with \texttt{onnxruntime.InferenceSession} and exposes a JSON endpoint `/api/v1/analyze` that accepts serialized flow windows and returns a classification result and an optional explanation (top-k influential nodes by attribution scores).

A minimal Dockerfile for production-like deployment is included and contains the following steps:

\begin{verbatim}
FROM python:3.10-slim
WORKDIR /app
COPY . /app
RUN pip install -r backend/requirements.txt
EXPOSE 8000
CMD ["uvicorn", "backend.app.main:app", "--host", "0.0.0.0", "--port", "8000"]
\end{verbatim}

Security in deployment includes running the server behind an authenticated reverse proxy, enforcing TLS, and restricting API keys. The server accepts only batched windows below a configured size to bound inference memory.

\section{Experimental Setup}

This section details dataset construction, baseline models, training hyperparameters, and evaluation methodology.

\subsection{Synthetic Dataset}

Real labeled malware flow corpora are often restricted, so we construct a synthetic dataset that mimics common malicious behaviors while allowing controlled experiments. The dataset generator produces graphs representing a sliding window of T = 300 seconds. Parameters used in experiments:

\begin{itemize}
	\item Number of graphs: 10,000 (8,000 train, 1,000 validation, 1,000 test).
	\item Nodes per graph: mix of small (10-50) and medium (50-500) graphs to test scale.
	\item Malicious rate: 10% of graphs labeled malicious.
	\item Malicious patterns injected: beaconing sequences, multi-stage downloads, coordinated scanning subgraphs.
\end{itemize}

Each node has $F_n = 16$ raw features after preprocessing. Edge features are $F_e = 8$ dimensional aggregated statistics.

\subsection{Baselines}

We compare the proposed GNN against the following baselines:

\begin{itemize}
	\item RandomForest (RF) trained on flat, aggregated features per window (mean/max of flow features, node counts).
	\item Convolutional neural network (CNN) applied to fixed-size flow feature grids constructed by padding or truncating short flow sequences.
	\item Recurrent neural network (LSTM) applied to ordered flow sequences extracted per host session.
\end{itemize}

Baselines are hyperparameter-tuned on the validation set.

\subsection{Training Hyperparameters}

The GNN training configuration used in experiments:

\begin{itemize}
	\item Layers: L = 3 message-passing layers.
	\item Hidden size: D = 128 per node embedding.
	\item Aggregation: mean for GraphSAGE messages, with edge-conditioned MLP of two layers (64 units).
	\item Batch size: 16 graphs per batch (with neighbor sampling for large graphs).
	\item Optimizer: AdamW with initial learning rate 1e-3 and weight decay 1e-5.
	\item Scheduler: ReduceLROnPlateau on validation AUC.
	\item Epochs: up to 100 with early stopping after 10 epochs without validation improvement.
\end{itemize}

Evaluation metrics: accuracy, precision, recall, F1-score, and AUC. We also measure inference latency (milliseconds per graph) using \texttt{onnxruntime} on a single CPU.

\subsection{Failure Modes and Error Analysis}

Common failure cases include:

\begin{itemize}
	\item Highly sampled telemetry where only a fraction of flows are available; this reduces graph connectivity and degrades detection of coordinated activity.
	\item Adversarial evasion where malware randomizes beacon intervals and endpoints to mimic benign background traffic.
	\item Small graphs where insufficient structural signal exists; in such cases flat-feature baselines can be competitive.
\end{itemize}

We analyze false positives and false negatives using per-example attribution scores (gradient-based or attention weights) and find that many false positives are benign scanning events with similar structural footprints to simulated malicious scanning.

\section{Security Considerations}

Using machine learning in security-sensitive domains introduces risks. We discuss poisoning, evasion, privacy, and operational hardening.

\subsection{Poisoning and Data Integrity}

If training data is poisoned, models may learn incorrect correlations. Mitigations include data provenance checks, anomaly detection on training data, robust training methods (trimmed losses), and maintaining a trusted labeled dataset for validation.

\subsection{Evasion and Robustness}

Malware may attempt to evade graph-based detection by minimizing structural footprints or blending with benign traffic. Defenses include adversarial training (augmenting training data with evasive patterns), randomized sampling strategies during training, and integrating host-level telemetry to increase signal diversity.

\subsection{Privacy}

Flow data can contain sensitive IP addresses and behavioral information. The pipeline supports data anonymization and aggregation (subnet-level nodes) and minimizes storage of raw identifiers in production by deriving feature hashes.

\section{Limitations}

Key limitations of this study include:

\begin{itemize}
	\item Synthetic dataset: while synthetic scenarios enable controllable experiments, they may not capture the full diversity of real-world malware behavior.
	\item Scalability: very large enterprise graphs require advanced sampling and distributed training beyond our current single-node experiments.
	\item Interpretability: although subgraph attributions help, full explainability for analyst workflows requires additional tooling.
\end{itemize}

We consider the problem of classifying network activity represented by flow records into two classes: benign or malicious. Let F = {f_1, f_2, ..., f_M} denote a collection of raw flow records collected over a time window T. Each record f_i contains attributes such as source and destination identifiers, ports, protocol, byte and packet counts, and timestamps. The task is to map the set F into a graph representation G = (V, E) and compute a label y \in {0,1} indicating whether the activity represented in the graph contains malicious behavior.

Formally, we define a flow-graph construction function C that maps the raw flow set to a graph:

\begin{equation}
G = C(F; \theta_C),
\end{equation}

where \theta_C denotes configuration parameters for the construction step (for example, aggregation windows, node type choices, and feature normalization parameters). Given a graph G and associated node and edge feature tensors X and E_f, the classifier is a parametrized function

\begin{equation}
\hat{y} = f_{\theta}(G, X, E_f)
\end{equation}

where \theta are learnable model parameters. The learning objective is to minimize a task loss over a labeled dataset D = {(G_i, y_i)}:

\begin{equation}
L(\theta) = \frac{1}{|D|} \sum_{i} \ell(f_{\theta}(G_i), y_i) + \lambda R(\theta),
\end{equation}

where \ell is a classification loss (for example binary cross-entropy), R is a regularizer and \lambda is a weight decay hyperparameter.

Key constraints and desiderata for the problem:

\begin{itemize}
	\item Scalability: the pipeline must process high-volume flow streams using aggregation and sampling strategies to bound memory and compute.
	\item Robustness: models should be resilient to missing or sampled telemetry, NAT-induced aggregation, and encryption that reduces available features.
	\item Interpretability: predictions should be accompanied by signals (for example influential nodes or subgraphs) to aid analysts.
	\item Deployability: trained models must be exportable (ONNX) and served with low-latency inference.
\end{itemize}

Evaluation metrics include accuracy, precision, recall, F1-score, area under the ROC curve (AUC), and operational metrics such as inference latency and memory footprint.

\section{Motivation}

There are several reasons to pursue a graph-based approach for malware classification on flow data.

First, many malicious behaviors are inherently relational. Examples include:

\begin{enumerate}
	\item Repeated beaconing: an infected host may contact a small set of command-and-control hosts at regular intervals. This pattern is more apparent when viewing flows as edges out of the infected node.
	\item Multi-stage downloads: a sequence of flows between different endpoints may be used to stage payloads or move laterally.
	\item Coordinated scanning: multiple hosts may exhibit correlated outbound connections indicative of a coordinated reconnaissance campaign.
\end{enumerate}

Second, flat feature models discard structural context. A single flow's byte count or duration may be insufficient to distinguish noisy benign traffic from malicious beacons. By contrast, GNNs can aggregate neighbor information to provide context-aware embeddings.

Third, operational deployments require compact models that can be deployed at scale. GNN architectures such as GraphSAGE allow for inductive learning where embeddings for unseen nodes can be computed by aggregating neighbor representations, enabling application in live networks with new hosts.

Challenges that motivate our specific design choices include:

\begin{itemize}
	\item Variable graph size: flow-graphs can range from small (a few nodes) to large (thousands of nodes) depending on the observation window; we therefore design batching and pooling strategies to work across sizes.
	\item Class imbalance: malicious events are rare; we incorporate class weighting, focal loss variants, or over/under-sampling to address imbalance during training.
	\item Feature heterogeneity: node features (e.g., host role, historical statistics) and edge features (e.g., bytes, duration) must be normalized and combined; edge-conditioned convolution or attention mechanisms help integrate these heterogeneous signals.
\end{itemize}

Taken together, these motivations make graph neural networks a compelling technology for flow-based malware detection, striking a balance between expressivity, inductive generalization, and deployability.

\section{Literature Review}

This section reviews prior approaches to network flow classification and positions graph neural networks relative to convolutional and recurrent neural networks. We focus on methods that operate on flow-level telemetry or short session aggregates.

Classical approaches use manual feature engineering and apply standard classifiers such as Random Forests, Support Vector Machines, or Gradient Boosted Trees. These approaches are simple to deploy but often require careful feature design and struggle to capture relational patterns across flows.

Deep-learning approaches have been explored to reduce reliance on manual features. Convolutional neural networks (CNNs) have been applied to flow byte sequences or to feature matrices constructed from fixed-size windows. Recurrent neural networks (RNNs) and their gated variants (LSTM, GRU) can model temporal sequences of flows for a single host or session. More recently, graph neural networks (GNNs) have been proposed to capture the relational structure inherent in communication graphs.

Discussion: CNNs excel when flow data can be organized into regular grids or when byte-level payload features are available. RNNs model ordered sequences well but do not capture cross-session relations naturally. GNNs explicitly model interactions and hence are well suited for cases where relations between endpoints or flows carry discriminative information.

Related work: Several papers apply graph learning to network security tasks. Representative examples include graph-based botnet detection, graph anomaly detection in enterprise telemetry, and GNN-based intrusion detection systems. We adapt standard GNN recipes from the literature while tailoring node and edge features to flow-level telemetry.

\subsection{GNN Advantages for Flow Data}

GNNs enable aggregation of neighbor context, which is valuable for detecting coordinated or multi-step behaviors. When edge attributes are incorporated (for example byte counts, durations, or temporal summaries), edge-conditioned convolutions or attention mechanisms can weight neighbor contributions by flow importance. Inductive variants such as GraphSAGE support generalization to new hosts by computing embeddings from neighbor attributes rather than fixed node identities.

\subsection{Limitations of Prior Work}

Many prior works assume full visibility and high-fidelity labels. In operational settings, sampling, NAT, and encrypted traffic reduce the available signal. Additionally, large enterprise graphs pose scalability challenges for GNNs; sampling and hierarchical pooling techniques are required for production-scale deployment.

\section{Proposed Methodology}

This section describes the end-to-end pipeline used in this work: flow graph construction, feature engineering, the GNN architecture, training protocol, and inference/deployment considerations.

\subsection{Overview}

The pipeline consists of the following high-level stages:

\begin{enumerate}
	\item Collect raw flow records in a sliding time window T and preprocess to normalize fields.
	\item Construct a directed flow graph G = (V, E) using the procedure in Section III, with node features X and edge features E_f.
	\item Batch graphs into mini-batches using padding or neighbor sampling to create inputs for the GNN.
	\item Train a GNN classifier using supervised labels and class-imbalance mitigation techniques.
	\item Export the trained model to ONNX for serving and provide a FastAPI endpoint for inference.
\end{enumerate}

\subsection{Network Flow Graph Construction}

The construction function C(F; \theta_C) maps a set of flow records F observed during a window T into a graph G. The steps are:

\begin{enumerate}
	\item Node definition: choose a node schema. In our implementation we use endpoint:port tuples as nodes. Each unique (ip, port) observed in T becomes a node v \in V. Optionally, endpoints can be anonymized or aggregated by subnet for privacy.
	\item Edge creation: for each flow record f = (s, d, sp, dp, proto, bytes, pkts, t_start, t_end), create a directed edge e_{u->v} from node u=(s,sp) to v=(d,dp). If multiple flows occur between the same node pair within T, aggregate them by computing summary statistics (sum of bytes, number of flows, average duration).
	\item Temporal bucketing: to preserve short-term temporal order, split T into B buckets and attach a bucket index to edges or create multi-edge temporal layers.
	\item Feature computation: compute per-node features such as degree, historical connection counts, role-based heuristics (server vs client), and per-edge features such as byte count, duration, packet rate, flags summary, and time-since-last-flow.
\end{enumerate}

Aggregating flows into edges reduces graph size and improves stability. The resulting graph has node feature matrix X \in R^{N \times F_n} and edge feature tensor E_f \in R^{|E| \times F_e}.

\subsection{Feature Engineering}

Good features are crucial. We standardize continuous features (z-score normalization) and bucketize categorical features (protocol, well-known port ranges). Example node features:

\begin{itemize}
	\item Historical degree (number of unique peers in prior window)
	\item Ratio of inbound to outbound bytes
	\item One-hot encoding of role guesses (server-like if large number of inbound connections)
\end{itemize}

Edge features include:

\begin{itemize}
	\item Total bytes and packets for the aggregated flows
	\item Average duration and inter-arrival times
	\item Flow count and byte rate
	\item Time-bucket index encoded as an integer or sinusoidal embedding for temporal awareness
\end{itemize}

All features are concatenated into dense vectors and passed through small input MLPs to produce initial node embeddings h_v^{(0)} and edge embeddings e_{uv}^{(0)}.

\subsection{GNN Architecture}

We design an architecture that combines GraphSAGE-style neighborhood aggregation, GCN normalization for stability, and edge-conditioned message passing to incorporate flow features.

\subsubsection{Edge-Conditioned Message Passing}

Standard message passing computes messages m_{u\to v} based on neighbor node representations h_u and optionally edge attributes e_{uv}. We use an edge-conditioned function:

\begin{equation}
m_{u\to v}^{(k)} = \phi_{\theta_m}^{(k)}\left( h_u^{(k-1)}, e_{uv}^{(0)} \right)
\end{equation}

where \phi_{\theta_m}^{(k)} is implemented as a small multilayer perceptron (MLP) whose parameters are shared across edges at layer k. The aggregation is a permutation-invariant operator such as mean, sum, or attention-weighted sum:

\begin{equation}
\overline{m}_v^{(k)} = \text{AGG}\left( \{ m_{u\to v}^{(k)} : u \in N(v) \} \right).
\end{equation}

The node update uses a gated update (GRU) or simple concatenation followed by an MLP:

\begin{equation}
h_v^{(k)} = \text{ReLU}\left( W^{(k)} \cdot [h_v^{(k-1)} \, || \, \overline{m}_v^{(k)}] + b^{(k)} \right).
\end{equation}

This formulation allows edge features to directly modulate messages.

\subsubsection{GraphSAGE and GCN Hybrid Layers}

We interleave GraphSAGE-style aggregation with GCN normalization. A hybrid layer can be written as:

\begin{equation}
H^{(k+1)} = \sigma\left( \tilde{A} H^{(k)} W_1^{(k)} + \text{AGG}(H^{(k)}) W_2^{(k)} \right),
\end{equation}

where the first term applies normalized adjacency (GCN-style) and the second term applies learned aggregation (GraphSAGE-style) to capture both global smoothing and local inductive aggregation.

\subsubsection{Temporal Pooling}

To classify a graph representing a time window, we need a graph-level representation. After L message-passing layers we compute a global readout r(G):

\begin{equation}
r(G) = \text{POOL}\left( \{ \text{MLP}_{read}(h_v^{(L)}) : v \in V \} \right),
\end{equation}

where POOL can be mean, max, or attention-based pooling. For temporal graphs with bucketed edges, we optionally compute bucket-level readouts and apply a temporal pooling (for example a small temporal CNN or attention over bucket readouts) to produce the final representation used for classification.

\subsubsection{Classification Head}

The readout r(G) is passed to a classification head (MLP) that outputs logits p = \text{softmax}(W_c r(G) + b_c) for multi-class tasks or a sigmoid for binary classification. We train using binary cross-entropy loss with optional focal loss modifications:

\begin{equation}
\ell_{BCE}(p, y) = -[y \log p + (1-y) \log (1-p)].
\end{equation}

Focal loss variant reduces the weight of easy negatives for class imbalance.

\subsection{Training Protocol}

Key training details:

\begin{itemize}
	\item Mini-batching: we use neighbor sampling and fixed-size padding to construct batches of graphs with bounded computation.
	\item Class imbalance: we apply class weights in the loss and experiment with focal loss and over-sampling of malicious graphs.
	\item Regularization: weight decay and dropout on MLP layers. Early stopping on validation AUC.
	\item Optimization: Adam or AdamW with learning rate scheduling (cosine or step decay).
	\item Reproducibility: fixed random seeds, deterministic data splits, and exporting training logs and model checkpoints.
\end{itemize}

\subsection{Implementation and Inference}

We implement the models in PyTorch with PyTorch Geometric or DGL-style message passing abstractions. For inference and deployment, models are traced/exported to ONNX and served through a FastAPI endpoint that accepts serialized flow windows, performs the same construction pipeline, and returns classification results and top-k influential nodes for analyst interpretation.

\subsection{Algorithmic Pseudocode}

\begin{verbatim}
Procedure TRAIN_PIPELINE(dataset D, epochs E):
	for epoch in 1..E:
		for batch in Batches(D):
			graphs = [ C(F_window) for F_window in batch ]
			node_feats, edge_feats, adj = PrepareBatch(graphs)
			h = InputMLP(node_feats); e = EdgeMLP(edge_feats)
			for k in 1..L:
				 m = MessagePass(h, e, adj)   # edge-conditioned messages
				 h = UpdateNode(h, m)
			r = Readout(h)
			loss = Loss( Classifier(r), labels )
			loss.backward(); optimizer.step(); optimizer.zero_grad()
	Save(best_model)

Procedure INFER(window F):
	G = C(F)
	h, e, adj = Prepare(G)
	h = InputMLP(h); e = EdgeMLP(e)
	for k in 1..L: h = GNNLayer(h,e,adj)
	r = Readout(h)
	return Classifier(r), Explain(h,adj)
\end{verbatim}
